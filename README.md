1. 專案背景與目標
1.1 開發動機
一般專注計時工具經常強調效率、任務完成率及時間管理，但使用者在讀書、工作或感到疲累時，有時候更需要的是「不用急著完成所有事，也有人安靜陪著」的感覺。因此，本專案嘗試把計時功能與療癒系像素場景結合，做成一個可以短暫停留的小房間。
網站不提供排名、連續登入獎勵或未完成懲罰，而是透過雨夜窗景、室內暖燈、兩隻小貓與溫和的文字回饋，讓使用者自行決定如何度過這段時間。
1.2 系統目標
- 降低開始的門檻： 從五分鐘開始，不要求使用者證明生產力。
- 提供低干擾陪伴： 使用者可以專注，也可以單純休息或發呆。
- 保留選擇權： 自行選擇陪伴模式、時長、音效與房間環境。
- 留下可回顧的紀錄： 記住已完成的陪伴時間，而不是評價表現。
1.3 目標使用者與範圍
目標使用者： 想在讀書、工作、休息或睡前放鬆時獲得陪伴感的學生、上班族，以及喜歡像素風格與簡單互動的人。
MVP 1.0 範圍： 單人、單頁、免登入的靜態 Web App。功能包含 2D 像素房間、四種模式、倒數計時、小貓互動、環境控制、情境文字與本地完成紀錄。
不包含： 真正的 AI 聊天、帳號系統、跨裝置同步、多人連線、家具自由擺放、裝飾解鎖、完整歷史日曆或回憶收藏。畫面中的 A NOTE FOR YOU 是隨模式變換的短句，不是回憶資料庫。
2. 使用情境與操作流程
使用者進入網頁後，看見一間有書桌、窗景、暖燈與兩隻小貓的房間。若想處理作業，可選擇「一起專注」及 25 分鐘；若只是想休息，也能選擇其他陪伴模式。按下開始後，計時器持續倒數，過程中可暫停、恢復或與小貓簡單互動。時間完成後，網頁提供對應回饋，並保存該次完成紀錄。
主要流程： 進入網站 → 選擇模式 → 選擇時長 → 視需要調整環境 → 開始／暫停／繼續 → 完成陪伴 → 查看今日紀錄。
3. 功能需求規格（Functional Requirements）
下列編號代表 MVP 1.0 必要需求（Must Have）。每項需求都有可觀察的行為，並可對應第 7 節驗收案例。
FR-01｜像素陪伴房間
子需求	預期行為
FR-01-01	進入網站後，顯示完整的 2D 像素房間，不需額外下載圖片或登入。
FR-01-02	場景包含雨夜窗景、書桌與檯燈、書架、床鋪、植物、窗台貓及地毯上的貓窩。
FR-01-03	場景以 384 × 252 Canvas 繪製，依畫面寬度等比例縮放，保留像素邊緣效果。
FR-01-04	小貓、雨滴或房間物件可呈現低干擾的基本動畫；使用者可關閉部分動態。


FR-02｜陪伴模式選擇
模式	使用情境	情境回饋
一起專注	讀書、工作、作業	鼓勵慢慢完成眼前的小事
安靜陪伴	不想被打擾，只想有人在	低干擾的共處文字
休息一下	短暫放鬆、喝水	休息與舒緩提醒
晚安放鬆	睡前或一天結束時	安靜的晚安回饋，場景偏夜間色調


- FR-02-01： 使用者在未開始計時或已完成計時時，可切換上述四種模式；預設為「一起專注」。
- FR-02-02： 切換模式後，情境狀態、提示文字與暖心短句須對應所選模式。
- FR-02-03： 進行中或暫停中的計時不可直接更換模式，避免單次紀錄歸類不一致；重設後可重新選擇。
FR-03｜陪伴倒數計時器
子需求	預期行為
FR-03-01	提供 5／15／25／50 分鐘四種預設時長；預設為 5 分鐘。
FR-03-02	按下「開始陪伴」後啟動倒數，顯示 MM:SS、進度條與進行中狀態。
FR-03-03	按下暫停後停止倒數並保留剩餘時間；繼續後由剩餘時間接續。
FR-03-04	計時進行或暫停時，不可直接修改模式與時長。
FR-03-05	按下重設後回到所選時長；放棄的未完成時段不得計入完成紀錄。
FR-03-06	倒數完成後更新畫面、顯示完成訊息，並只登記一次有效紀錄。
FR-03-07	使用實際截止時間校正倒數；回到背景分頁或重新開啟頁面時，應依保存的時間狀態更新。


狀態規則： idle（尚未開始）→ running（倒數中）↔ paused（暫停中）→ complete（已完成）。重設會回到 idle。這是操作狀態，不是評分機制。
FR-04｜小貓互動
子需求	預期行為
FR-04-01	點擊「打聲招呼」可從目前模式的預設句子中顯示一段回應。
FR-04-02	點擊「摸摸小貓」可觸發短暫的文字回應及貓咪抬頭、耳朵／尾巴與愛心效果。
FR-04-03	小貓互動不應打斷計時器，也不需要外部 AI API。


FR-05｜環境與音效控制
子需求	預期行為
FR-05-01	「窗外雨景」可切換 Canvas 中的雨滴效果。
FR-05-02	「暖暖燈光」可切換室內光暈與暗色效果。
FR-05-03	「開啟音效」由使用者主動觸發，播放合成環境雨聲；未啟用時保持靜音。
FR-05-04	音量滑桿範圍為 0～100，可調整輸出音量。
FR-05-05	關閉雨景時，同步停止雨聲；若音效已啟用，完成計時仍可播放提示音。
FR-05-06	「小動畫」開關可停用部分場景動態，避免持續動效干擾。


FR-06｜情境文字與回饋
- FR-06-01： 不同模式分別提供開始語、招呼回應、完成語及暖心短句。
- FR-06-02： 開始、暫停、繼續、重設及完成後，應更新相應的狀態與文字提示。
- FR-06-03： 文字使用預先設計的規則與句庫，不宣稱能理解使用者心情，也不支援自由對話。
FR-07｜今日陪伴紀錄
子需求	預期行為
FR-07-01	一段正式計時完成時，保存所選模式、時長與完成時間。
FR-07-02	「今天，我們一起」區塊顯示當地日期的累積分鐘數、完成次數及紀錄清單。
FR-07-03	統計以完成當下的裝置當地日期為準，完成後即更新畫面。
FR-07-04	同一次完成事件不可重複登記；中途重設的時段不納入統計。


FR-08｜本地資料保存
- FR-08-01： 使用 localStorage 保存模式、時長、雨景／燈光／音量／動畫等偏好、計時狀態及完成紀錄。
- FR-08-02： 重新整理或重新開啟相同網站來源時，應讀取已保存資料；進行中計時依截止時間恢復或校正。
- FR-08-03： 若瀏覽器限制本地儲存，應顯示提示；主要即時操作仍可進行，但無法保證下次開啟仍有紀錄。
- FR-08-04： 為遵守瀏覽器音訊限制，即使偏好曾啟用，重開頁面後仍需使用者操作才會開始播放聲音。
4. 非功能需求規格（Non-functional Requirements）
ID	類別	規格與驗證方向
NFR-01	部署與可攜性	完整網站封裝於單一 index.html，可直接由瀏覽器開啟或部署於 GitHub Pages；不需後端、API Key、外部圖片或第三方 JS 函式庫。
NFR-02	響應式介面	桌面版以房間與控制面板雙欄呈現；手機較窄螢幕（約 760px 以下）改為上下排列，核心操作不應被遮擋。
NFR-03	操作回饋	按鈕切換應有文字、視覺或數值狀態回饋；計時進行中限制不允許的模式／時長操作。
NFR-04	音訊與動態	音效不自動播放；提供動畫控制，並參考系統 prefers-reduced-motion 設定。
NFR-05	隱私	不需要帳號，紀錄僅保存在瀏覽器本地，不主動上傳使用者資料。
NFR-06	資料限制告知	清除瀏覽資料、無痕模式、跨裝置或不同網站來源，均可能造成資料不可共用或遺失；同時開啟多個分頁可能發生狀態不同步。
NFR-07	視覺一致性	網頁使用奶油米白、鼠尾草綠、暖棕與灰紫色；2D 像素場景是主視覺，控制面板以低干擾卡片式介面呈現。

6. Vibe Coding 與需求變更紀錄
這次開發先透過與 AI 討論主題、受眾、互動需求與 MVP 範圍，再由 Codex 建立可操作原型；正式需求文件則依據原型回饋進一步修訂，使最終規格與實作一致。
迭代階段	原有想法／發現的問題	調整決策與成果
01｜概念發想	想做具有療癒感的網頁，但一般電子寵物、解謎或單純休息空間都不完全符合期待。	將核心需求定義為「陪伴使用者專注或休息」，而非追求遊戲通關或效率排名。
02｜需求收斂與 Mockup	需要兼顧陪伴氛圍、真正互動及 GitHub Pages 單檔限制。	選擇 2D 像素場景、四種模式、計時器、簡單互動與本地儲存，作為 MVP 1.0。
03｜Codex 初版	AI 快速產出房間與功能，但原本坐在桌前的人類角色不夠自然。	保留計時及環境控制，局部修改人物外型。
04｜第二輪視覺修正	人物比例、表情、坐姿，以及與桌椅的空間關係仍不理想。	透過更具體的提示要求調整比例與遮擋關係，並重新檢視設計目標。
05｜設計轉向	持續修整人物未能有效提升「被陪伴」的感覺。	移除人類角色，改為窗台貓與貓窩裡的小貓，並同步調整對話文案。
06｜規格對齊	初期想像的回憶收藏、角色自主生活等較大型功能不適合本次時間與技術範圍。	將正式規格限定為已實作的 MVP，將未完成項目歸入未來擴充。


本次學習重點： Vibe Coding 的價值不只是讓 AI 寫程式，更在於透過預覽發現需求與畫面落差、具體描述問題、要求局部修改，甚至調整原本的設計方案。這次保留了「低壓力陪伴」的核心，但改變了陪伴感的視覺呈現方式。

8. 使用方式與部署
線上使用： https://cynthia-liao.github.io/together-five-minutes/
本地使用： 下載 index.html，以支援 Canvas 與 JavaScript 的現代瀏覽器開啟即可；不需安裝套件或啟動伺服器。
GitHub Pages： 在公開 Repository 的根目錄放入 index.html 與 README.md，前往 Settings → Pages → Deploy from a branch，指定 main 及 / (root) 作為發布來源。
