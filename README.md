1. 專案背景與設計理念
常見的專注計時工具著重效率、完成進度與生產力，但有時候使用者需要的只是「有人陪著，慢慢開始」。本專案嘗試將倒數計時與療癒系互動場景結合，提供一個沒有排行榜、沒有失敗懲罰，也不要求持續操作的陪伴空間。
在《一起，再五分鐘》中，陪伴者不是聊天機器人，而是一間溫暖的小房間，以及兩隻安靜待著的像素小貓。使用者可以選擇專注、安靜共處、休息或睡前放鬆，依照自己的節奏度過一段時間。
核心目標：
1. 降低開始的心理負擔： 從五分鐘開始也可以。
2. 提供安靜的陪伴感： 利用場景、貓咪互動、環境聲與短句取代催促。
3. 保留使用者自主權： 自由選擇陪伴模式、時間與房間氛圍。
4. 讓時間被記住： 記錄已完成的陪伴時段，而非評價工作成果。
2. 目標使用者與使用情境
目標使用者是想在讀書、工作或休息時擁有低干擾陪伴感的學生、上班族，以及喜歡像素藝術與療癒互動體驗的人。
典型使用流程： 使用者打開網頁，看到雨夜窗景、溫暖燈光和窩著的小貓；選擇「一起專注」與 25 分鐘，按下開始後自行讀書或工作。中途可以暫停，也可以打招呼、摸摸貓咪；時間結束後，網頁顯示溫柔回饋，並將完成紀錄保存在本機瀏覽器中。
3. MVP 1.0 功能規格
ID	功能	規格與預期行為
FR-01	像素陪伴房間	以 Canvas 2D 繪製固定的 384 × 252 像素場景，包含雨夜窗景、書桌、檯燈、書架、床鋪、植物、窗台小貓與地毯貓窩。畫面依容器等比縮放。
FR-02	四種陪伴模式	「一起專注」「安靜陪伴」「休息一下」「晚安放鬆」。每種模式有相應的狀態、開始語、招呼回應、完成語與暖心短句。計時進行或暫停時，暫時停用模式切換。
FR-03	陪伴計時器	可選擇 5／15／25／50 分鐘；支援開始、暫停、繼續及重設；顯示剩餘時間、進度條與狀態文字。
FR-04	計時狀態保存	使用時間戳記計算剩餘時間，降低背景分頁造成的誤差；透過 localStorage 保存進行中／暫停的計時狀態，重新開啟時可接續或校正。未完成而重設的時段不列入完成紀錄。
FR-05	小貓互動	「打聲招呼」隨機顯示目前模式的回應；「摸摸小貓」觸發貓咪抬頭、尾巴／耳朵細微動作與愛心效果，並更新畫面文字。
FR-06	環境設定	可以分別開關窗外雨景、暖暖燈光、環境音效與小動畫，並透過滑桿調整音量。
FR-07	環境音與完成提示	使用 Web Audio API 合成雨聲與提示音；預設不自動播放聲音，需使用者主動開啟。關閉雨景時，雨聲也隨之關閉。
FR-08	今日陪伴紀錄	完成計時後記錄陪伴模式、時長和完成時間；顯示今天的完成次數、累積分鐘數及紀錄清單，重新整理後可從本機保存資料讀取。
FR-09	回饋文案	根據模式、開始、暫停、繼續與完成狀態呈現不同的溫柔文字；沒有自由輸入對話或生成式 AI 聊天。
FR-10	響應式介面	桌面以左側房間、右側控制面板雙欄排版；窄螢幕改為上下排列，保留主要操作功能。


3.1 計時器運作規則
- 預設模式為「一起專注」，預設時間為 5 分鐘。
- 開始： 進入倒數狀態，更新進度與提示文字。
- 暫停： 保留剩餘時間，使用者可以稍後繼續。
- 繼續： 從暫停處恢復倒數。
- 重設： 放棄本次未完成時段並回到所選時長，不累計紀錄。
- 完成： 顯示完成訊息，將時段寫入當日紀錄；同一次完成不重複加入。
- 重新整理： 嘗試恢復已保存的狀態；進行中的倒數以實際時間差校正。
- 統計日期： 依瀏覽器所在裝置的當地完成日期計入「今日」資料。
3.2 房間與小貓互動
房間有兩隻貓：一隻在窗台邊安靜休息，另一隻窩在地毯的貓窩裡。場景不需要持續對話才能運作。點擊「摸摸小貓」會產生短暫的動作與愛心回饋，讓使用者在不打斷主要活動的情況下獲得陪伴感。
3.3 本版本的功能範圍
MVP 1.0 不包含帳號登入、跨裝置同步、多人連線、聊天 AI、家具自由擺放、房間解鎖系統或完整歷史日曆。畫面中的「A NOTE FOR YOU」是依陪伴模式切換的短句區，不是已實作的回憶收藏功能。
4. 介面與視覺設計規格
4.1 視覺風格
網站以低飽和奶油米白與鼠尾草綠作為介面主色，搭配暖棕木質家具、灰紫色夜景、暖黃色室內燈光。房間場景採用低解析度 Canvas 繪圖與像素化等比放大；網頁控制區則以簡潔卡片式介面呈現，兼顧療癒氛圍和操作清晰度。
4.2 介面配置
區塊	內容
頁首	作品名稱與簡短導引文字
左側主區	像素房間、情境對話、小貓互動按鈕
左側設定區	雨景、燈光、音效開關與音量滑桿
右側控制區	四種陪伴模式、時長選擇、倒數計時、開始／暫停／繼續／重設
右側資訊區	暖心短句、當日分鐘數與完成次數、完成紀錄
頁尾	小動畫開關與安靜的收尾文字


4.3 使用體驗原則
- 不使用懲罰、排名或高壓催促。
- 操作後應有對應的數值、文字、音效或畫面變化。
- 環境音不自動播放，動畫可由使用者關閉。
- 優先維持房間的陪伴氛圍，讓控制介面輔助而非主導整個畫面。

技術	使用目的

所有網站程式碼皆放在單一 index.html 中，沒有後端、外部圖片、CDN 函式庫或 API 金鑰需求。因此可以直接使用瀏覽器開啟，亦可部署於 GitHub Pages。
已知限制： 儲存資料只存在目前瀏覽器及網站來源下，無法在不同裝置間自動同步；清除網站資料可能遺失紀錄；瀏覽器限制音訊自動播放，必須手動啟用；同時在多個分頁操作同一網站可能造成狀態不同步。頁面目前只展示當日紀錄，而非可瀏覽所有日期的歷史頁。
6. Vibe Coding 與 AI 協作迭代
本作品的開發不只是將一句想法交由 AI 生成程式，而是經過需求討論、視覺預覽、發現問題與反覆修正。
階段	決策、發現與調整
01. 發想方向	從一般療癒型 Web App 的構想出發，最後聚焦在「安靜共處」而非虛擬寵物養成或傳統待辦清單。
02. MVP 規劃	將功能收斂為單頁像素房間、四種模式、陪伴計時器、少量互動、環境設定及本機紀錄，以符合短時間開發與單檔部署要求。
03. Mockup 討論	比較插畫風與 2D 像素風後，選擇更容易以 Canvas 製作互動場景的像素風，確認雙欄介面與暖色系設計。
04. AI 初版實作	利用 Codex 產生單一 index.html，建立房間繪圖、計時器、模式切換、音效及紀錄邏輯。
05. 人物視覺修正	初版以坐在書桌前的人類角色呈現陪伴感；實際預覽後發現人物比例、坐姿及桌椅透視不自然，嘗試針對角色局部修改。
06. 設計方向調整	重新評估「陪伴感」的視覺來源，將人類角色改為房間與小貓，新增窗台貓與地毯貓窩，並同步改寫原本過度擬人化的文字。
07. 規格對齊與發布準備	以最終 HTML 對照 README 功能需求，保留已實作的內容，將尚未完成的回憶收藏、裝飾解鎖等項目列為未來擴充。


主要學習： AI 可以快速建立可操作的網頁，但初步生成結果不代表最適合使用者。透過實際觀看、操作與迭代，才能讓功能、構圖及作品想傳達的情感一致。

8. 執行與 GitHub Pages 部署
本地執行
下載或複製 index.html，以現代瀏覽器開啟即可。無須安裝套件或啟動後端伺服器。
發布到 GitHub Pages
1. 建立一個 Public GitHub Repository。
2. 將 index.html 和 README.md 放在 Repository 根目錄並提交。
3. 前往 Settings → Pages。
4. 在 Build and deployment 中選擇 Deploy from a branch。
5. 選擇 main 分支、/ (root) 目錄並儲存。
6. 等待部署完成，開啟 GitHub Pages 網址實際測試。
最終 GitHub Repository 可以只包含這兩個檔案：
TogetherFive/
├── index.html    # 可操作的完整網站
└── README.md     # 專案介紹與規格書
